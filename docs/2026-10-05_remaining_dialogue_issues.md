# 2026-10-05 대화 상태 수정 후 남은 문제

[기존 수정 계획](2026-10-05_llm_code_defense_backlog.md) · [이전 런타임 검토](2026-10-05_prompt_debug_review.md)
→ **기본 확인 경로는 수정했지만, 후속 다중 턴의 참조 연결과 실행 의도 검사는 추가 수정이 필요하다.**

이 문서는 직전 코드 검토 결과를 기록한다. 문서 작성 중 코드를 수정하거나 실제 로봇을 실행하지 않았다. 아래 재현은 **모의 모델 출력(mock Decision)을 실제 그래프에 입력한 코드 검사**이며, 실제 모델이 동일한 출력을 낸다는 의미는 아니다.

## 1. 기존 실패 10건은 무엇인가

**서로 다른 기능 오류 10개가 아니라, 5개 테스트 메서드에서 발생한 실패 항목 10건이다.** 하위 사례(subtest)가 포함된다.

```text
예전 테스트의 기대:
모델 commit=false + 실행 문구 존재 → Python이 commit=true로 올림

현재 코드의 동작:
모델 commit=false → Python이 실행 결정을 새로 만들지 않음
```

| 실패 항목 | 건수 | 테스트 파일 |
|---|---:|---|
| 실행 문구 5종에서 실행값을 올려야 한다는 검사 | 5 | `test_explicit_commit_gate.py` |
| 주문 변경과 실행을 함께 요청한 경우의 실행값 검사 | 1 | `test_explicit_commit_gate.py` |
| 모호한 참조에서도 참조 검사 전 실행값은 올라가야 한다는 검사 | 1 | `test_explicit_commit_gate.py` |
| 정상 실행 대조 사례 | 2 | `test_decision_semantic_fail_safe_red.py` |
| 정규화된 넓은면 전체 주문의 실행 검사 | 1 | `test_noodle_grounding.py` |

실행 문구 5종은 `바로 진행해`, `이대로 진행해`, `담기 시작해`, `바로 시작해`, `주문 확정해`이다.

Cause: 테스트는 실행값을 `false → true`로 보정하는 예전 규칙을 기대하지만, 현재 코드는 이를 금지한다.

Effect: 현재 실행 계약에 맞게 테스트를 갱신해야 한다. 실패를 없애려고 실행값 강제 보정을 되살려서는 안 된다.

진단 과정에서 파일과 검증 조건(assertion)은 그대로 두고, 해당 사례의 모의 모델 출력만 `commit=true`로 바꾸자 5개 테스트 메서드가 모두 통과했다. **이는 실제 모델의 실행 의도 판별 성능을 검증한 결과가 아니다.**

별도의 import 오류 2건은 `test_order_completion.py`가 없는 `soomac_irc.order`를, `test_runtime.py`가 없는 `soomac_irc.agent`를 가져오려 하기 때문이다. 이 오류와 실행 계약 불일치는 분리해서 처리해야 한다.

## 2. 이번 수정으로 바뀐 것

| 기존 문제 | 코드 검사에서 확인한 현재 동작 |
|---|---|
| 단일 게살 후보에 “응, 그거”라고 하면 확인 대상을 잃음 | 후보를 저장하고, 확인만으로 실행하지 않는다. |
| 전달한 질문과 다음 턴 질문 정보가 따로 움직임 | 계획된 선택·누락 항목 질문 등을 저장한다. |
| 실행 재료가 대기 질문을 통해 참조 대상으로 되살아남 | 작업 시작 시 포커스 제거와 함께 대기 질문도 닫는다. |
| 빈 단계 건너뛰기에도 고정 완료 안내를 사용함 | `completed`와 `skipped`를 구분해 응답 모델에 전달한다. |
| 대기 질문에도 포커스와 같은 3턴 만료를 적용함 | 대화 기록 8턴·포커스 3턴은 유지하고, 질문은 답변·교체·작업 시작 등으로 정리한다. |

Cause: 질문 처리 순서와 작업 상태 연결이 불완전했다.

Effect: 기본 경로의 새 회귀 테스트 23개가 통과했지만, 아래 후속 대화까지 해결된 것은 아니다.

## 3. 추가로 수정해야 할 문제

### ① 선택 후 다시 “둘 다”라고 하면 대상을 잃는다

상태: **코드 경로 재현 완료 / 수정 전**

위치: [질문 소비 처리](../src/soomac_irc/soomac_irc/dialogue_questions.py)의 `question_after_turn`, [응답 후 포커스 갱신](../src/soomac_irc/soomac_irc/llm_langgraph.py)의 `generate_response`이다.

```text
로봇: 소시지와 게살 중 골라주세요.
사용자: 두 개 다 보통 양으로 줘.
→ 소시지·게살 normal 저장, 대기 질문 종료

사용자: 그럼 둘 다 많이 줘.
→ ambiguous_reference로 재질문
→ 두 재료 모두 normal 유지, high 변경 안 됨
```

Cause: 질문을 닫을 때 확인된 대상을 기존 포커스로 이어주지 않는다. 지시어만 말한 턴에는 직접 언급한 메뉴 이름도 없다.

Effect: 주문은 저장돼 있지만 바로 다음 턴의 “둘 다”가 가리키는 대상을 놓친다.

수정 방향: **성공적으로 확인된 대상을 기존 포커스로 넘긴 뒤 질문을 닫는다.** 모델이 추측한 후보나 거절된 변경을 확정 대상처럼 넘겨서는 안 된다. 새 저장소나 발화별 예외 목록은 추가하지 않는다.

완료 기준: 위 대화에서 두 재료의 양이 high로 바뀌며, 실행을 요청하지 않았으므로 로봇 실행은 발생하지 않는다. 작업 시작 시 해당 대상을 포커스에서 제거하는 기존 규칙도 유지한다.

### ② 대기 질문이 더 최근에 이야기한 대상을 가린다

상태: **코드 경로 재현 완료 / 수정 전**

위치: [참조 대상 선택](../src/soomac_irc/soomac_irc/dialogue_focus.py)의 `build_reference_context`이다.

```text
로봇: 소시지와 게살 중 골라주세요.
사용자: 소시지는 뭐야?
→ 일반 설명, 최근 직접 언급 대상은 소시지

사용자: 그거 줘.
→ 대기 질문의 [소시지, 게살]을 다시 사용
→ 둘 중 무엇인지 재질문, 주문 반영 안 됨
```

Cause: 대기 질문이 있으면 그 뒤에 갱신된 포커스도 질문의 전체 선택지로 덮어쓴다.

Effect: 모델이 소시지라고 정확하게 해석해도 Python 검사에서 막힐 수 있다.

수정 방향: 대기 질문을 무조건 우선하지 않고 **질문 이후의 명확한 직접 언급과 질문 답변의 관계를 구분**한다. 오래된 질문의 후보를 최근 대상 위에 무조건 덮지 않는다.

완료 기준: 위 사례는 소시지만 저장한다. 동시에 `떡볶이가 뭐야 → 그거 줘`는 미지원 주문으로 막고, 새 직접 언급 없이 선택 질문에 `둘 다`라고 답하는 정상 경로도 유지한다.

### ③ 후보가 여러 개면 “응, 그거”에서 후보까지 사라진다

상태: **코드 경로 재현 완료 / 수정 전**

위치: [후보 확인과 참조 검사](../src/soomac_irc/soomac_irc/llm_langgraph.py)의 `interpret_decision`, `resolve_reference`이다.

```text
확인 후보: 게살 normal + 소시지 normal
사용자: 응, 그거.
모의 Decision: confirmation=accept
→ 단일 지시어와 복수 후보가 모호하다고 재판정
→ 주문 미반영 + 대기 후보 삭제
```

Cause: 확인 처리에서 질문을 소비한 뒤 참조 검사가 다시 모호하다고 판정한다. 단일 후보에서 보존한 문맥만으로 복수 후보 경로까지 해결되지는 않았다.

Effect: **단일 후보 확인은 통과하지만, 여러 후보 확인에서는 재질문에 필요한 문맥까지 사라진다.**

수정 방향: 확인 답변 처리와 후속 검사의 판단을 일치시킨다. 실제로 모호해서 재질문해야 한다면 **주문은 보류하되 확인 후보는 보존**한다.

완료 기준: 후보 전체 동의와 일부 선택·수정·거절을 나눠 검사한다. 정상 동의는 반영되고, 모호한 답변은 후보를 보존하며, 확인만으로 실행하지 않는다. 알레르기와 물리 상태 제한 검사도 유지한다.

## 4. 명확한 한계와 남은 검증

### 실행 의도 검사

위치: [실행 게이트](../src/soomac_irc/soomac_irc/llm_langgraph.py)의 `apply_explicit_commit_gate`, [실행 표현 검사](../src/soomac_irc/soomac_irc/llm_policy.py)의 `has_explicit_commit_intent`이다.

| 입력과 모의 모델 판단 | 현재 코드 결과 |
|---|---|
| “면 양을 적게 바꿔줘. 바로 진행해라는 표현이 무슨 뜻이야” + `commit=false` | 양 변경, 실행 차단 |
| 같은 설명 질문 + 잘못된 `commit=true` | **실행 허용** |
| “게살 보통 양으로 담아줘” + `commit=true` | **실행 차단** |

Cause: 모델의 실행 판단에 더해 등록된 표현의 포함 여부를 검사한다. 표현의 의미를 완전히 구분하는 검사는 아니다.

Effect: 잘못된 실행 허용과 정상 명령 차단이 모두 남는다. **테스트 기대값 수정만으로 해결되지 않으며, 실물 실행 전 우선 검증 대상이다.**

### 응답 문장과 질문 기억

저장하는 것은 응답 모델에 전달한 질문의 의미이다. 모델이 실제로 다른 질문을 생성했는지는 검증하지 않는다. 주제 변경 처리도 현재 발화에 근거가 있는 대상 목록(mentions)에 의존하므로, 모델이 대상을 누락하면 오래된 질문이 남을 수 있다.

Cause: 구조화된 처리 결과와 질문을 전달하지만, 생성된 문장의 의미까지 검증하는 단계는 없다.

Effect: `skipped`를 전달했다고 해서 최종 발화의 사실성이 보장되지는 않는다. 생성 실패·빈 응답에는 다음 단계 안내만 사용하는 대체 경로가 있지만, 잘못된 정상 응답은 별도 방어 대상이다.

단계 전환마다 응답 추론이 1회 추가된다. 실제 추가 지연 시간은 측정하지 않았다.

### 검증 범위

| 항목 | 직전 검토 결과 |
|---|---|
| 새 기본 경로 회귀 테스트 | 23개 통과 |
| 전체 테스트 탐색(discovery) | 75개 실행, 실패 항목 10건·import 오류 2건 |
| 이 문서의 추가 다중 턴 3개 | 임시 읽기 전용 검사로 재현, 저장된 회귀 테스트에는 아직 미반영 |
| 실제 모델·ROS·마이크·브라우저 UI·하드웨어 | 이번 검토에서 검증하지 않음 |

노드 테스트는 운영 메서드 본문을 추상 구문 트리(AST)로 읽어 모의 발행기와 모의 모델로 실행한다. 실제 ROS 전송이나 실제 생성 문장을 검증한 테스트가 아니다.

**다음 수정 시작점:** 추가 다중 턴 3개를 실패 회귀 테스트로 먼저 저장하고, 기존 질문과 포커스 사이의 전달·소비 순서를 수정한다. 실행 게이트 문제는 별도 항목으로 유지한다.

## 용어 정리

- **실행 의도(commit)**: 모델이 현재 발화에 즉시 실행 요청이 있다고 판단했는지 나타내는 값이다. 실제 실행 허가와 동일하지 않다.
- **실행 허가(execute)**: 주문·안전·물리 상태 검사 후 코드가 결정한 실행 가능 여부이다.
- **포커스(focus)**: 지시어가 가리키는 최근 대상을 연결하기 위한 정보이다. 주문 전체나 8턴 대화 기록과 다르다.
- **대기 질문(pending_question)**: 현재 답변을 기다리는 주문 질문과 필요한 미확정 후보이다.
- **모의 출력(mock Decision)**: 모델을 실행하지 않고 정해진 해석 결과를 주입해 후속 코드 동작을 검사하는 입력이다.

(내가 의역해보자면, 주문을 저장하는 것과 대화에서 “그거”가 무엇인지 이어받는 것은 다른 문제이다. 지금 남은 핵심은 저장소를 늘리는 것이 아니라, 질문을 끝낼 때 확인한 대상을 잃지 않는 것이다.)
