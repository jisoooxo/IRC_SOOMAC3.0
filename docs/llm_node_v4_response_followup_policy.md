# LLM Node V4 응답 후 다음 행동 안내 정책

- [`llm_node_v4.py`](../src/soomac_irc/soomac_irc/llm_node_v4.py) — 정책·자유·VLM 응답을 최종 발행하는 코드이다.

→ **응답 내용은 모델이 만들 수 있지만, 실제 주문 상태와 다음 행동은 Python이 확정해야 한다.**

## 1. 확인된 문제

주문 변경 성공 응답이 `요청한 주문 변경을 반영했어요.`에서 끝나 사용자가 다음에 무엇을 말해야 하는지 알기 어렵다.

실행 로그 14번 턴에는 더 위험한 사례도 있다. Tool action은 `respond`이고 실제 `active_task`는 `None`인데, 자유응답 모델이 `육류 담기를 시작할게요.`라고 말했다. **실제 로봇 상태와 자연어 응답이 서로 달랐다.**

(내가 의역해보자면 모델은 말을 자연스럽게 만드는 역할인데, 로봇이 실제로 움직였는지까지 말로 결정해 버린 것이다.)

## 2. 중앙 후처리란 무엇인가

중앙 후처리(central post-processing)는 여러 경로에서 만든 응답을 사용자에게 보내기 직전에 한곳에서 마지막으로 정리하는 단계이다.

```text
Tool 정책 응답 ─┐
자유응답 모델 ──┼─→ 최종 응답 검사·다음 행동 추가 ─→ UI/TTS 발행
VLM 응답 ───────┘
```

쉽게 말하면 **모델이 작성한 문장을 바로 방송하지 않고, 안내 데스크가 실제 주문표를 확인한 뒤 마지막 안내 문장을 붙이는 것**이다.

예시는 다음과 같다.

```text
모델/정책 응답: 요청한 주문 변경을 반영했어요.
현재 실제 상태: 면 종류와 면 양이 아직 없음
최종 응답: 요청한 주문 변경을 반영했어요. 다음으로 면 종류와 면 양을 말씀해 주세요.
```

중앙 후처리는 문장의 사실 여부도 검사한다. `active_task=None`인데 응답이 `담기를 시작할게요`라고 주장하면 그대로 발행하지 않아야 한다.

## 3. 자유응답 프롬프트도 바꿔야 하는가

**바꿔야 한다. 다만 프롬프트는 1차 방어이고 Python 검사가 최종 방어이다.**

현재 프롬프트에도 주문 변경이나 작업 시작·완료를 말하지 말라는 지시가 있지만, 실제 로그에서 모델이 이를 위반했다. 따라서 더 명확하게 역할을 제한해야 한다.

```text
사용자의 질문에 대한 설명만 작성한다.
주문 선택 확정, 로봇 작업 시작·완료, 다음 단계 이동을 주장하지 않는다.
다음 주문 행동은 Python이 별도로 붙이므로 작성하지 않는다.
```

이렇게 하면 자유응답 모델은 `할머니와 먹을 때 어떤 재료가 좋은지` 같은 질문에만 답한다. `현재 무엇을 골라야 하는지`, `작업을 시작했는지`는 검증된 주문 상태에서 Python이 작성한다.

(여기서 프롬프트를 강하게 해도 100% 보장은 안 되는구나. 그래서 상태 검사가 마지막에 필요하다.)

## 4. 적용 범위

| 응답 경로 | 중앙 후처리 동작 |
|---|---|
| 주문 변경·중복·일부 차단 | 현재 단계의 미선택 항목 또는 진행 방법을 붙인다. |
| 확정 실패·추천 실패·취소 거절·파싱 실패 | 실패 이유 뒤에 지금 가능한 다음 행동을 붙인다. |
| 자유응답·장면 설명 | 질문 답변 뒤에 검증된 현재 단계 안내를 붙인다. |
| 추천 확인·제외 재확인 | 이미 구체적인 질문이 있으므로 중복 안내를 붙이지 않는다. |
| 작업 시작·VLM 판정·자동 단계 전환·주문 완료 | 사용자 입력을 기다리지 않으므로 다음 선택 질문을 붙이지 않는다. |

## 5. 데이터 추가가 필요한가

**현재 문제를 고치는 데 추가 학습 데이터는 필요하지 않다.**

원인은 Tool adapter가 주문값을 추출하지 못한 것이 아니라, 여러 응답 경로가 최종 안내 규칙을 공유하지 않는 데 있다. 따라서 우선순위는 다음과 같다.

1. Python 중앙 후처리를 구현한다.
2. 자유응답 프롬프트의 역할을 질문 답변으로 제한한다.
3. 실제 로그를 회귀 테스트 사례로 만든다.
4. 수정 후 새 로그에서 상태와 발화가 일치하는지 확인한다.

추가 학습 데이터는 Tool action이나 메뉴값 추출 오류가 반복될 때만 검토한다. 예를 들어 같은 의도의 발화가 여러 로그에서 지속적으로 `respond`와 `set_order` 사이에서 잘못 분류된다면 그때 분류·Tool 호출 데이터를 보강한다.

## 6. 필요한 테스트 데이터

학습 데이터와 테스트 데이터는 구분해야 한다. **학습용 대화 증가는 필요 없지만, 회귀 테스트용 사례는 추가해야 한다.**

- 주문 일부만 선택한 뒤 다음 필수값을 안내하는 사례
- 같은 값을 다시 말한 뒤에도 다음 행동을 안내하는 사례
- 추천·취소·확정 실패 뒤 가능한 행동을 안내하는 사례
- `respond`가 작업 시작·완료를 거짓 주장하지 않는 사례
- 작업 중·VLM 판정 중에는 새 선택 질문을 붙이지 않는 사례

## 용어 정리

- **자유응답(free reply)**: Tool 호출 없이 사용자의 질문이나 잡담에 자연어로 답하는 모델 출력이다.
- **정책 응답(policy reply)**: 검증된 transaction 결과만 사용해 Python이 만드는 고정 응답이다.
- **중앙 후처리(central post-processing)**: 최종 발행 직전에 응답과 실제 상태를 대조하고 다음 행동을 붙이는 공통 단계이다.
- **회귀 테스트(regression test)**: 수정한 문제가 이후 변경에서 다시 발생하지 않는지 확인하는 테스트이다.
- **Tool adapter**: 사용자 발화를 `set_order`, `confirm_section`, `respond` 같은 구조화된 action으로 변환하는 모델 계층이다.

## 7. 결정

**자유응답 프롬프트는 보강한다. 다음 행동 생성과 로봇 상태 주장은 모델에 맡기지 않고 Python 중앙 후처리에서 결정한다. 현재는 학습 데이터 대신 로그 기반 회귀 테스트를 추가한다.**
