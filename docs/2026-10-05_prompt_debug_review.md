### 면 종류와 다음 질문

사례 03의 내부 값은 다음과 같다.


Cause: scalar 주문값에 대한 발화 근거 검사가 없어서 잘못된 면 선택이 통과한다. Response가 target을 무시한 생성 원인은 불명(cause unknown)이며 입력 target 자체는 정상이다.
Effect: 잘못된 주문 저장과 잘못된 다음 질문이 동시에 발생한다. `next_prompt` 생성 로직의 실패로 오해하면 안 된다.

### 인용문을 실행으로 바꾼 Python 게이트

사례 11의 두 번째 턴이다.

```text

{"route":"mixed","order":{"noodle_portion":"low"},"queries":[{"type":"robot_status"}]}

policy.execute: true
```

Cause: `has_explicit_commit_intent()`가 문장 전체의 부분 문자열로 실행 표현을 찾고, `apply_explicit_commit_gate()`가 모델이 생략한 commit도 true로 올린다. 인용 범위나 설명 요청을 제외하지 않는다.

### 남는 코드 방어 대상

1. **복합 설명문의 잘못된 실행:** `면 양을 적게 바꿔줘. 바로 진행해라는 표현이 무슨 뜻이야`에서 모델은 양 변경만 출력한다. `llm_langgraph.py:339`의 게이트가 commit을 true로 바꾼다. 순수 뜻 질문도 게이트 뒤 재판정이 1회 필요했다.
2. **단독 미지원 요청의 안내:** `떡볶이 줘`는 clarify로 안전하게 멈추지만 `llm_langgraph.py:718`에서 Response 호출 없이 `요청을 제대로 이해하지 못했습니다. 다시 말씀해 주세요.`를 반환한다. 프롬프트의 제공 불가 안내 규칙에 도달하지 않는다.
3. **면·STT·질문 대상의 보장:** 이번 모델 출력은 개선됐지만 scalar 근거 검사, STT 정규화, 구체적 재질문은 미구현이다. 문자열 입력 시험으로 음성 인식 개선을 주장할 수 없다.

Cause: 명령 게이트와 고정 응답 분기는 프롬프트 이후에 실행되는 Python 정책이다.
Effect: 안전을 위해 실제 의도를 왜곡한 route/clarify를 만들지 않았으며, 남은 실패는 [후속 코드 방어 목록](2026-10-05_llm_code_defense_backlog.md)에 남겼다.
