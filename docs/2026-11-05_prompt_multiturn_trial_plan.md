# D6 프롬프트·멀티턴·실행 안내 비교 계획

상태: **5/5 평가·실패 추적·기록 완료.** [결과](2026-11-05_prompt_multiturn_trial_review.md) · [실제 시연 대본](2026-11-05_verified_multiturn_scenarios.md). 미해결 오류/서버 실행 간 변동을 남긴 조건부 결과이며 운영 배포는 없다.

## 1. 사용자 판정 반영

소스만 추천받은 뒤 ‘그걸로 담아줘’에 소스 선택 후 면 실행을 다시 묻는 응답은 **정상**이다. 이전 원본 점수·raw·동결 target은 보존하고 최신 사용자 재판정을 별도 기록한다. 그 뒤 미도달8턴은 성공으로 바꾸지 않는다. 이번에는 선택 후 별도 실행 요청까지 실제로 이어간다.

## 2. 프롬프트와 입력 동결

기존 규칙에도 general/task 구분·일시적 기분 저장 금지가 존재한다. Decision에 짧은 우선 판별 규칙·대조 예시를 추가하는 후보를 만들고 기존 prompt와 비교한다. 음식 취향은 유지하며 못 먹는 제한과 단순 덜 매운 선호를 구분한다. 소스 후보 수락과 면의 명시적 실행을 구분한다. 운영 agent_prompts.py 대신 평가용 system_prompt 인자로 전달한다.

기존 D117과 새 대조 문항, 필수17턴·수량정정·모호성·추천 수락·명시적 면 실행·일반대화·취향·제한·부정 실행을 포함한 누적 대화를 후보 출력 전에 동결한다. 구정답에서 사용자 판정이 달라진 문항은 새 복사본에 이유를 남긴다. 이 실험은 개발 선택 시험이며 비노출 일반화 시험이 아니다.

## 3. 토큰·CPU 사전검사

**사용자 추가 지시: 평가 vLLM max_model_len과 max_num_batched_tokens를16384로 확대한다.** 클라이언트 모델 한도16384, D/Q 입력15360(출력1024), P 입력15872(출력512)로 함께 맞춘다. 기존 운영 설정은 수정하지 않고 평가 프로세스에서만 적용한다. 실제 tokenizer/template로 Decision 입력+출력1024, Q/P 각각의 출력 예약을 포함해 검사한다. 정적 prompt와 상태 여유1024, 동결 입력,20메시지 history 및 repair를 측정한다. 추가 prompt 때문에 정상 history를 잘라 해결하지 않는다. 처음10240용 보강안은 정적 여유 검사에서8365+1024>9216으로 실패했고 축약안도8204+1024>9216이었다. 사용자의 확대 지시에 따라 원래 보강안을 복원한다. 이 실패 기록과 축약 후보는 보존한다. 실제 요청의 길이/입력 자료형/추가 history trim도 기록한다.

## 4. 실제 vLLM 비교

16384 한도와 batch 크기로 바뀌므로 이전10240의 baseline 결과를 새 실행으로 가장하지 않는다. 같은 D6/Q6/Pbest150에서 기존prompt/fixed, 보강prompt/fixed, 기존prompt/model, 보강prompt/model 4조건을 순차 실행한다. 모델과 어댑터를 한 번 올린 임시18001 서버를 사용한다. 각 대화의 실제 답변을 다음 history에 넣으며 gold D를 주입하지 않는다. **실패한 턴에서도 실제 잘못된 state/history를 유지한 채 후속 대화를 끝까지 진행한다.** 기대 상태/단계는 별도로 유지하며 첫 오류와 그 이후 관측을 구분한다. 정답 state로 교체하지 않는다. 명시적 사용자 재요청/정정을 통해 회복되는지 확인한다. HTTP/엔진 장애는 의미 실패와 구분해 기록한다. 단순route차이와 위험한 주문/실행오류는 구분한다. 실물 완료는 표시된 offline fixture이다.

## 5. 판정·기록·정리

수량/허위완료/실행 여부와 추천 후보·제한·취향·route를 각각 검수한다. 프롬프트가 실패를 줄였는지와 기존 성공을 망가뜨렸는지를 함께 보고, 고정 안내 ON/OFF의 실제 문장·호출시간·후속멀티턴 영향을 기록한다. 실패도 최종 결과로 보존하며 성공 대화는 시연 후보 MD에 사용자 발화/모델답변/계획을 남긴다. worklog와 결과를 갱신하고 임시서버/GPU/포트를 반환한다. 운영 적용은 이번 평가에서 수행하지 않는다.

서버 기동 근거: 16K/.45는 KV5.25GiB 필요·2.67GiB 확보로 실패했다. 로그를 FAILED_STARTUP_01에 보존하고 평가 GPU 할당률만.58로 올려 KV6.77GiB/21,106tokens를 확보했다. 실제 서버16,384 및 선택adapter 경로 확인. 운영 설정 변경 없음.
