# 2026-10-05 LLM 후속 코드 방어 목록

[실측 결과와 로그](2026-10-05_prompt_debug_review.md)
→ **일부 구현 완료**이다. 프롬프트 검증 후 사용자가 실행 게이트·응답 분기 스니펫을 적용했고, 이어서 승인된 STT 별칭과 면 종류 근거 검사를 구현했다. 아래의 재현 설명은 수정 전 기록이며 현재 상태는 우선순위 표와 마지막 구현 기록을 따른다.

프롬프트만 수정했던 시점에는 `널적면` 추측과 `햄 → 소시지` 치환이 모델 출력에서 사라졌고, `떡볶이가 뭐야 → 그거 줘`는 제공 불가로 답했다. 당시 복합 뜻 질문의 실행 오판과 단독 미지원 주문의 generic 답변은 남았다. 해당 시점의 증거는 [2차 검증](2026-10-05_prompt_debug_review.md#2차-검증--프롬프트만-수정)에 보존한다.

## P0 — 인용문 실행 게이트

대상: `src/soomac_irc/soomac_irc/llm_policy.py:324`의 `has_explicit_commit_intent`, `llm_langgraph.py:339`의 `apply_explicit_commit_gate`이다.

재현은 정상 주문을 먼저 저장한 후 다음 발화를 넣는 것이다.

```text
면 양을 적게 바꿔줘. ‘바로 진행해’라는 표현이 무슨 뜻이야
```

모델은 commit을 출력하지 않았는데 최종 commit과 execute가 true였다. 넓은면 1회 가상 PLAN이 발생했다. 물음표 없는 순수 설명에서는 general/commit 모순에 대한 재판정으로 실행이 막혔으므로, 순수 설명만 검사해서는 이 결함을 찾지 못한다.

Cause: 문장 전체에 대한 부분 문자열 검사가 인용된 실행 표현에도 반응한다.
Effect: 실제 실행 요청 없이 주문 변경만 한 턴이 로봇 작업을 시작할 수 있다.

후속 설계: 실행 표현이 사용자 명령에 속하는지, 인용·예시·질문·부정에 속하는지 구분해야 한다. 단순히 `route=general`만 제외하면 mixed 재현을 막지 못한다. 모델 판단을 무조건 믿는 방식으로 기존 게이트를 없애는 것도 해결안으로 확정하지 않는다.

완료 기준:

1. 위 mixed 발화는 양 변경만 반영하고 `execute=false`, PLAN 없음이어야 한다.
2. 인용 설명의 물음표 유무와 따옴표 종류에 관계없이 실행하지 않아야 한다.
3. 실제 `면 양을 적게 바꾸고 바로 진행해`는 필요한 조건이 충족되면 실행 가능해야 한다.
4. 질문·제안·부정 차단에 대한 기존 회귀 테스트를 유지해야 한다.

## P1 — 면 종류 근거 검사

대상: `src/soomac_irc/soomac_irc/llm_policy.py:374`의 `find_decision_grounding_errors`이다. 현재 직접 대상 검사는 `order_patch.toppings` 중심이며, `noodle_type` 값의 발화 근거를 검사하지 않는다.

실측: `널적면으로 주세요`와 오늘의 mixed 원문 모두 `얇은면`으로 저장됐다. 반면 `보통면으로 주세요`는 이번 모델 실행에서 clarify로 차단됐다. 한 표현이 통과했다고 Python 방어가 갖춰진 것은 아니다.

Cause: 스키마가 허용하는 면 종류면 사용자 발화의 의미와 달라도 저장까지 통과한다.
Effect: 나중의 정상 실행 명령이 이미 잘못 저장된 주문을 실행할 수 있다.

후속 설계: 명확한 현재 메뉴 표현, 승인된 정규화 결과, Python이 확정한 reference를 근거로 인정한다. 추천 선택·확인 응답은 기존 전용 경로를 보존한다. 원문과 정규화문을 모두 추적할 수 있어야 한다. 근거 없는 값은 다른 메뉴로 자동 수정하지 않고 clarification으로 보낸다.

완료 기준:

1. 정규화되지 않은 `널적면`을 모델이 얇은면으로 출력해도 state에 저장하지 않는다.
2. `보통면`으로 얇은면/넓은면을 임의 선택하지 않는다.
3. `보통 양`만으로 면 종류가 생성되지 않는다.
4. 정상 메뉴, 명확한 reference, 추천 선택·확인 흐름이 기존대로 동작한다.

## P1 — STT 메뉴 정규화

대상: `src/soomac_irc/soomac_irc/stt_hotword.py:5`의 `MENU_WORD_REPLACEMENTS`, 관련 검사 파일 `src/soomac_irc/test/test_stt_hotword.py`이다.

이번에 실제 함수를 호출한 결과이다.

| 입력 | 현재 정규화 결과 | 후속 목표 |
|---|---|---|
| `널적면` | `널적면` | 승인된 별칭으로 취급할 경우 `넓은면` |
| `넓적면` | `넓은면` | 유지 |
| `넙적면` | `넓은면` | 유지 |
| `보통면` | `보통면` | 임의 보정하지 않고 재질문 |

Cause: 정규화 목록에 `널적면`이 없다.
Effect: 해당 문자열이 LLM까지 전달되어 모델이 면 종류를 추측한다.

후속 설계: `널적면 → 넓은면`과 띄어쓰기 변형을 좁은 범위로 추가한다. `햄 → 소시지`, `보통면 → 넓은면` 같은 의미 추측은 정규화에 넣지 않는다. 코드 방어와 같은 canonical 메뉴 체계를 사용한다.

완료 기준: 위 표와 띄어쓰기 변형을 함수 테스트로 검증하고, 양쪽 STT 경로에서 동일한 정규화 함수를 통과하는지 확인한다. **이번 디버그는 STT를 우회하여 문자열을 직접 넣었으므로 실제 마이크 성능이 검증된 것은 아니다.**

## P2 — 고정 재질문과 질문 대상 보호

대상: `src/soomac_irc/soomac_irc/llm_langgraph.py:718`의 고정 응답 분기 및 `llm_policy.py`의 `build_next_prompt`/응답 전달 경계이다.

`보통면`과 `햄 빼줘`는 안전하게 멈췄지만 모두 다음 문장으로 끝났다.

> 요청을 제대로 이해하지 못했습니다. 다시 말씀해 주세요.

Cause: pure task의 understanding 분기는 Response Agent를 호출하지 않고 Python 고정 문자열을 반환한다.
Effect: 프롬프트만 바꿔서는 어떤 항목을 다시 말해야 하는지 안내할 수 없다.

또한 사례 03에서는 `next_prompt.target=noodle_portion`인데 Response가 “얇은 면과 넓은 면 중 어떤 면으로 할까요?”라고 출력했다. Python의 next_prompt는 맞았고 모델이 질문 대상을 바꿨다.

후속 설계: Python에서 확인된 사유와 대상만으로 재질문을 만든다. 이유를 판단할 수 없는 경우에는 기존 generic 문장을 남긴다. missing_field 질문은 target별 고정 문장으로 보호하는 방안을 검토한다.

| 확인된 사유·대상 | 목표 문장 예시 |
|---|---|
| 면 종류 불명확 | `얇은 면과 넓은 면 중 어떤 면을 말씀하신 건가요?` |
| 미지원 햄 | `햄은 현재 제공하지 않아요. 어떤 재료를 빼드릴까요?` |
| 단독 미지원 음식 요청 | `떡볶이는 현재 제공하지 않아요.` |
| 면 양 누락 | `면 양은 적게, 보통, 많이 중 어떻게 할까요?` |

완료 기준: 위 예시가 추측 없이 확인된 사유에서만 나오고, `next_prompt.target`과 실제 질문 항목이 일치한다. mixed의 일반 질문 응답도 유지한다.

2차 추가 관측: `떡볶이 줘`는 `reason=understanding`이고 Response 호출 기록이 비어 있어, 강화한 제공 불가 프롬프트가 적용될 기회 자체가 없다. 반면 설명 다음 턴의 `그거 줘`는 `unsupported_reference`로 기존 제공 불가 분기를 탄다. **직접 지목한 미지원 메뉴와 지시어로 지목한 미지원 메뉴의 사용자 안내를 일치시켜야 한다.** 경로를 억지로 general/mixed로 바꾸는 프롬프트 우회는 적용하지 않았다.

추가 완료 기준: `떡볶이 줘`, `떡볶이가 뭐야 → 그거 줘`, `떡볶이 줘. 그리고 떡볶이가 뭐야 → 그거 줘` 모두 주문·실행 없이 제공 불가를 알린다. `떡볶이랑 라면은 어떻게 달라 → 그거 줘`처럼 후보 전부가 미지원인 경우에도 제공할 수 있다는 인상을 주는 후보 선택 질문만으로 끝내지 않는다. 지원 메뉴 `양파가 뭐야 → 그거 줘`의 정상 추가는 보존한다.

## P2 — 응답 근거와 일반지식

대상: `src/soomac_irc/soomac_irc/response_model.py`, `agent_prompts.py`의 Task/General/Mixed 응답 경계이다.

사례 10에서 `session.order.noodle_type=얇은면`인데 응답은 “널적면 보통 양을 반영했어요”였다. 사례 05·10은 고대 로마 기원 오류도 반복했다. 사실 확인 근거는 [검증 결과 문서](2026-10-05_prompt_debug_review.md)의 Kew 링크에 있다.

Cause: 주문 사실을 설명할 때 최신 state 대신 원문의 표현을 사용하는 경계 위반이 관측됐다. 모델이 해당 문장을 생성한 내부 원인은 불명(cause unknown)이다.
Effect: 응답만 들으면 내부 주문 오인식을 발견하기 어렵고, 일반지식 오류는 강화된 프롬프트 이후에도 그대로 전달된다.

후속 설계: 주문 사실과 다음 질문은 canonical 값으로 만들고, 일반대화 부분은 별도로 생성·검증하는 방안을 검토한다. 사실 검증 자료를 제공하거나 확인 불가 응답으로 제한하는 것은 별도 제품 선택이며, 이번 요청만으로 일반대화를 전면 차단하지 않는다.

관측된 자연스러움 문제도 함께 보관한다: “면은 넓은 면과 보통 양으로”, “면 양을 적게로”, 소스·양 변경 중 일부만 안내하는 응답이다. 정량적인 자연스러움 점수는 측정하지 않았다.

## 디버그 실행 전제

현재 `llm_langgraph_debug.py:39`의 차단 목록에 `rail_move_ahead_pub`이 없다. 운영 노드는 이 publisher를 생성하며 이후 단계 안내에서 사용한다. 다음 디버그 유지보수 때 누락을 반영하고 새 publisher가 생겨도 테스트에서 검출되도록 해야 한다.

Cause: 디버그 코드가 publisher를 고정 목록으로 관리한다.
Effect: 새 토픽이 추가되면 실물 제어 출력이 디버그에서 누락될 수 있다. 이번 시험은 전용 실행기에서 추가 차단했고 실제 출력은 없었다.

## STT 보정·면 종류 근거 검사 구현 기록

[공통 STT 보정](../src/soomac_irc/soomac_irc/stt_hotword.py) · [면 근거 검사](../src/soomac_irc/soomac_irc/llm_policy.py) · [새 회귀 테스트](../src/soomac_irc/test/test_noodle_grounding.py)
→ 사용자가 승인한 `널적면 → 넓은면`만 추가했고, 근거 없는 면 선택은 저장·실행 전에 차단한다.

1. `널적면`, `널적 면`, 중간 공백이 여러 개인 `널적   면`은 `넓은면`으로 보정한다. `보통면`, `햄`, `페퍼로니`는 임의 치환하지 않는다.
2. CLOVA의 `stt_node.py`와 Nemotron의 `stt_nemotron_node.py` 모두 기존 공통 `normalize_stt_text()` 결과를 발행한다. 양쪽 모두 이미 원문/보정문 차이를 로그로 남긴다. 노드 자체는 수정하지 않았다.
3. Decision이 선택한 `order_patch.noodle_type`이 현재 발화의 정규 메뉴 표기 또는 Python이 확정한 참조 대상에 없으면 기존 safe-clarify 경로로 보낸다. 모델 mentions나 이전 주문만으로 새 선택을 허용하지 않는다. 이 경로는 해당 턴의 주문 변경을 전체 보류한다.
4. 정규화되지 않은 `널적면`을 디버그에 직접 넣으면 근거 검사에서 멈춘다. STT를 거친 `넓은면`은 정상 저장하며, 이를 모델이 얇은면으로 잘못 출력해도 차단한다. 추천 선택과 확인 응답은 기존 전용 경로를 유지한다.

Cause: 음성 인식의 확정 문자열을 보정하는 곳과 모델의 주문값을 검사하는 곳이 별개이다.
Effect: 승인된 오인식은 공통 STT에서 복구하고, 남은 근거 없는 면 선택은 Python에서 차단한다. 면 이름이 문장에 있다는 사실만 검사하므로 부정·비교·설명 등 모든 문장의 의미를 검증하는 것은 아니다.

검증: 새 면 근거 테스트 10개와 STT 테스트 추가 2개를 포함해 실행 가능한 테스트 **47개 통과**이다. 전체 discovery는 `test_order_completion`의 `soomac_irc.order`, `test_runtime`의 `soomac_irc.agent` 모듈 부재로 import 오류 2개가 남는다. 둘 다 수정 전 baseline에도 동일하게 발생했다. 실제 마이크, STT 모델, LLM 모델, 로봇 하드웨어는 이번 회귀 시험에서 실행하지 않았다.
