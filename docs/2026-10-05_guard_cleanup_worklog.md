### B. 제약 질문이 쌓이던 문제 (llm_langgraph.py, decision_model.py)

| 전 | 후 |
|---|---|
| 알러지가 확인 대기 사본(`candidate_session`) 안에만 있음 | **즉시 실제 주문 상태에 저장** |
| "응/아니" 답이 없으면 확인 질문이 영원히 남음 | **다음 1턴만 유효**. 답이 없으면 닫고, 보류한 메뉴만 버림 |
| 늦게 "응"하면 몇 턴 전 세션으로 통째 복귀 | 보류한 메뉴(`held_patch`)만 **현재 상태 위에** 적용 |
| 확인 대기 중에도 실행 허용 | 알러지가 실제 상태에 있어 실행 검사가 막음 |
| 충돌 없는 변경까지 같이 보류 | 충돌한 메뉴만 보류, 나머지는 반영 |
| 모델 입력에 세션 전체 사본을 넘김 (학습 때 본 적 없는 형식) | **학습 데이터와 같은 형식** `{"type", "conflicts": [{"item"}]}` 으로 넘김 |

### C. 남은 추천안이 몰래 적용되던 문제 (llm_langgraph.py)

- 추천을 받은 뒤 사용자가 직접 메뉴를 고르면 추천을 닫는다.
- "소시지만" 다음 "바로 시작" 때 게살이 들어가지 않는다.

### D. 응답 문장 (response_model.py, llm_policy.py, llm_langgraph_node.py)

| 추가한 응답 입력 | 목적 |
|---|---|
| `starting_now` | 실행 시 지금 담을 재료. 노드의 task 생성과 같은 함수(`section_execution_items`)를 쓴다 |
| `changed_this_turn` | 이번 턴 변경이 있었는지 true/false |
| `already_set` | 요청값 중 이미 같은 값이던 것. Python 상태 비교로 계산 |

프롬프트 규칙 추가 (응답 공통):
- 변경이 없으면 반영했다고 말하지 않기
- 직전 답변 반복하지 않기
- 이미 있는 값과 제한은 "이미 들어 있다"고 말하기
- 실행이 안 됐으면 담기·시작한다고 말하지 않기

## 3. 남은 계획

### P0 — 응답 모델의 거짓 실행 안내 막기

**문제**: 실행이 안 됐는데 응답이 "담기 시작할게요"라고 말한다.

```text
17:55 #9 "버섯 알러지가 있는데 양판은 먹을게"
Decision commit=true → 실행 게이트가 막음 (정상) → execute=false
응답 입력: execution_authorized=false, starting_now=[]   ← 정확함
응답: "…양파를 포함하여 담기 시작할게요."              ← 거짓
```

- 원인: 응답 모델이 입력의 실행 여부를 무시하고 발화("먹을게")와 대화 흐름을 따라갔다 (추측).
- 결과: 사용자는 로봇이 움직인다고 착각한다. 프롬프트 규칙("절대 말하지 않는다")은 넣었지만 확률만 낮춘다.

**방향: 문장을 지우지 않고, Decision repair 처럼 응답을 한 번 다시 추론한다.**

```text
응답 생성 → 위반 감지 → 위반 사실을 붙여 1회 재추론 → 다시 감지 → 그래도 위반이면 fallback
```

정해야 할 것은 **위반 감지 방법**이다.

| | 감지 방법 | 단어 하드코딩 | 확실성 | 비용 |
|---|---|---|---|---|
| 1 | 응답 스키마에 `claims_execution: bool` 을 추가해 모델이 스스로 표시. `true` 인데 `execute=false` 면 재추론 | 없음 | 낮음 (모델이 거짓 표시 가능) | 거의 없음 |
| 2 | 같은 모델에 판정만 따로 묻기: "이 문장이 로봇이 지금 담기 시작한다고 말하는가? yes/no" (XGrammar enum 으로 강제) | 없음 | 중간~높음 | 판정 1회 약 1초 |
| 3 | 실행 표현 4개(`시작할게`, `담을게`, `담기 시작`, `진행할게`)로 문장 검사 | 단어 4개 | 높음 | 없음 |

- 추천: **2** (단어 없이 가능하고, 생성과 판정을 분리하면 모델이 자기 문장을 다시 읽게 된다)
- 재추론 시 붙일 정보: `"repair": {"violation": "execution_claim_without_authorization", "execution_authorized": false}`. Decision 의 `repair` 와 같은 패턴이다.
- 재추론도 실패할 때의 fallback: 위반 문장만 빼거나 고정 안내로 대체하는 것 중 정해야 한다. 고정 안내는 문장 하드코딩이다.
- 실행 경로(`execute=true`)에서는 감지를 돌리지 않는다. 지연은 실행 안 된 턴에서만 생긴다.
- 위치: `response_model.py` 의 `call_response`. 재추론은 Response 단계 안에서 끝내고 graph 는 바꾸지 않는다.
- 완료 기준: 17:55 #9 재현 시 실행 안내가 없을 것. 실행 턴의 응답은 그대로일 것. 감지 결과를 trace 에 기록할 것.
- 예상: 1시간 + 실제 모델 재실행 10분
