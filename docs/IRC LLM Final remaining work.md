## 2. 최우선: 추천 없이도 D→상태→P가 맞아야 한다

실제 경로는 `사용자 발화 + history + 이전 state → D raw/정규화 → 주문 적용·검증 → 최종 state/policy/next_prompt → P 입력/출력 → 발행·history`이다. **D JSON을 P에 그대로 복사하는 것이 아니며 Q를 매번 호출할 필요도 없다.** 실행 시작 등 기존 deterministic 경로는 P 미호출로 기록한다.

| 최초 어긋나는 지점 | 반드시 기록할 값 | 처리 방향 |
| --- | --- | --- |
| D부터 재료·양·제약·commit 누락 | 실제 입력, raw, sparse target, normalized, repair 전후, 독립 기대 변화 | D 의미 누락. Python이 사용자 문장을 다시 파싱해 채우지 않음 |
| D는 맞는데 주문 적용 후 사라짐 | before, patch, 검증 허용/거절 및 사유, after, 보호된 field | 정상 안전 거절과 Runtime 버그를 구별. 허용 주문이 코드에서 유실되면 최소 코드 수정 후보 |
| after는 맞는데 P input이 옛 값/다른 값 | confirmed_order, applied_this_turn, pending, next_prompt, 실제 serializer 입력 | 전달/계약 문제. 모델 재학습으로 덮지 않음 |
| P input은 맞는데 말이 다름 | P raw, 허용 사실, 금지 주장, 수량/대상/시제 | Response 의미 실패. 키가 유효한 JSON이어도 잘못된 값·주장은 실패 |
| P raw와 실제 발화/다음 history가 다름 | graph_reply, published_reply, 고정/fallback 출처, delivery 기록 | Node/발행/기록 경로 문제. 호출되지 않은 P를 오답으로 세지 않음 |

사용자의 “없는데 면 보통이라고 한다”는 **새 보고된 반례**로 보존한다. 정확한 세션/턴을 찾기 전에는 이번에 새로 재현했다고 쓰지 않는다. 이미 확인한 근접 증거는 best_stack의 면 종류 누락 뒤 허위 선택 발화와 17:39 T11의 소시지 high 입력→normal 응답이다. 서로 다른 사례를 동일 사건으로 합치지 않는다.

### 2.1 필수 대조 — 주문 해석·필드 보존

| 문맥/발화 예시 | 기대 변화 | 보존/금지 |
| --- | --- | --- |
| 면 미선택, “면은 얇은면으로 보통 양으로 골라줘” | noodle_type=얇은면, noodle_portion=normal | 주문 선택일 뿐 임의 실행/완료 아님 |
| 면 미선택, “보통 양으로” | 문맥상 면 양이면 portion만 normal; 대상 자체가 모호하면 명확화 | 얇은면/넓은면 종류를 임의 생성 금지 |
| 얇은면 선택됐고 양 미정, 수량 생략 신규 선택 | 독립 oracle에 따라 새 양 normal | 이것을 현재 없는 면 종류 생성으로 확대 금지 |
| 기존 확정량 low/high, 수량 생략 | 기존량 유지 | 매번 normal로 덮지 않음. 이번 수락 후보에 양이 있으면 그 근거도 구분 |
| 양파low·버섯low, “버섯만 보통으로 바꿔줘” | 버섯 normal | 양파 low, 소스·면·제약 등 불변 |
| 새 항목 추가 / “그거 빼줘” / “아까 그대로” | 지시 대상과 물리 가능성에 맞는 patch | none은 취소 patch, persisted order에서 삭제. 완료 재료를 실제 제거했다고 주장 금지 |
| “게살 알레르기가 있으니 소시지만 많이” | 게살 allergy 추가 + 소시지 high | 주문만 맞고 제한 누락이면 실패. 실제 게살이 안 담겼다는 이유로 합격 금지 |

### 2.2 필수 대조 — 주문과 실행을 동사로 가르지 않는다

같은 메뉴·양·history에서 `넣어줘/담아줘/골라줘`, `바로/지금`, 부정·조건·인용·미래 계획을 교차한다. 일반 선택, 확정 주문 실행, 추천 수락, 추천 수락+실행, 실행 유예, 취소를 구분한다. **“담다=commit, 넣다=주문” 또는 “바로 포함=commit” 규칙을 만들지 않는다.**

새 주문+명시 즉시 실행은 order+commit을 함께 판단한다. 추천 후보를 받아 실행한다면 confirmation=accept+commit 또는 명시 주문 선택+commit의 합법 경로를 대조한다. 정상 execution pending의 수락도 유지한다. 안전·필수 주문·busy·중복 실행 검증은 모두 그대로이다.

### 2.3 필수 대조 — P가 없는 사실을 채우지 않는다

- `confirmed_order.noodle_type=null`이면 면 종류 확정 주장을 하지 않는다. 수량 normal 존재와 면 종류 선택은 다르다. 반대로 실제 확정량이 있으면 매번 다시 묻지 않는다.
- “선택했어요/바꿨어요”, “시작해요”, “완료했어요”는 각각 적용 결과·실행 근거·실제 완료 근거에 대응한다. order 저장만으로 제조 완료를 말하지 않는다.
- pending/next_prompt가 없는데 실행 질문을 창작하지 않는다. 필수 정보가 부족하면 해당 누락 정보를 묻도록 계약을 점검한다. 모든 질문을 금지하지 않는다.
- D 누락 뒤 실제 after가 비어 있으면 P가 사용자 희망을 주문에 들어간 사실처럼 말하면 안 된다. upstream 오류를 말로 감추지 않는다.
- 이전 assistant가 틀린 수량을 말한 history도 보존하고, 현재 authoritative state와 최신 사용자 정정을 구분한다. 모순이 해소되지 않았으면 해결된 척하지 않는다.

원인: Q를 잘 정렬해도 직접 주문의 D 누락과 P 사실 오류는 남을 수 있다.
결과: D→P를 독립 필수 경로로 검증하고, Q 경로와 합쳐 평균으로 실패를 숨기지 않는다.

## 3. 연결 데이터와 평가 설계 — 아직 생성하지 않았다

후속 CQ01~05는 기존 A~E의 확장/정밀화이며 별도 전면 재감사가 아니다. 수량 **값·대상·신규/변경/무변경·선택/실행/완료**를 각각 검수한다. commit은 앞선 실제 질문·후보·현재 사용자 수락/변경을 함께 판단하며 Python 단어 trigger로 보충하지 않는다. latency는 정확성과 분리 보고하고 history 삭제나 오류 있는 빠른 답으로 개선을 주장하지 않는다. 사용자 임시 단계 고정 안내의 모델 복귀는 별도 승인·회귀 후이다.

1. **독립 정답 먼저:** 같은 dialogue/turn의 의도, 바뀔 필드·보존 필드·금지 변화·질문 목적을 작성한다. 반드시 복합 history 전체와 발화 역할을 읽고, 그래도 경쟁 해석이 남는 경우만 HOLD/명확화로 처리한다. 지시어·pending=null 자체로 모호함 판정을 하지 않는다. 같은 마지막 문장에 서로 다른 history를 붙인 대조를 포함한다. 현 모델 출력이 자동 gold는 아니다.
2. **두 종류를 분리:** 정상 학습 흐름은 올바른 D 적용 뒤 state와 P target을 연결한다. 실패/회복 진단은 실제 잘못된 D·state·history를 보존하되 P가 그 상태에 없는 주문을 했다고 말하도록 target을 쓰지 않는다. gold D 주입 진단은 실제 누적 성공과 별도이다.
3. **한 원천의 조건부 행:** D→P와 D→Q→P, 이벤트 Q→P, 기존 고정 발화 경로를 나눈다. 실제 호출된 모델만 학습행으로 만든다. state trace, field diff, source/hash/semantic_key, 계약 버전, split, HOLD 근거는 감사 sidecar이며 새 Runtime 필드가 아니다.
4. **대조·언어·분포:** 긍정/부정, 주문/추천/실행, 기존값/null/미지정량, 새 제약/이미 저장된 제약, 조사·구어·수음 변형, 2/3/6/8/12턴 복합 참조를 검수한다. 표현만 바꾼 동일 골격 증식·항상 크림/normal/commit/clarify로 몰리는 편향을 보고한다. 같은 입력의 모순 정답을 좋은 SFT target으로 넣지 않는다.
5. **누수·채택:** 기존 확정 ledger와 먼저 연결해 재사용/FIX/DROP/HOLD/신규만 구분한다. 대화 family 단위 split, few-shot·학습·평가 겹침, 토큰·target mask·history 보존을 검사한다. F01을 새 train에 편입하면 seen 회귀로 표기하고 별도 unseen family를 확보한다. 원본·봉인된 split·실패 증거는 덮지 않는다.

검증은 `gold 입력의 P 단독`, `실제 D 적용 결과의 P`, `모델 실제 답변을 history에 누적한 전체 흐름`을 분리한다. 첫 실패 뒤 진행 불가는 NOT_REACHED, 강제 수정으로 진행한 경우는 diagnostic이다. 구조 통과와 의미/자연스러움 판정은 별도이며 문구 정규식은 flag일 뿐 최종 의미 판정기가 아니다.

### 4.1 시연 후보와 확인 경계

면 얇은면 normal+느끼한 소스 추천 → 크림 명시 선택·실행 확인 → 양파/버섯 low → 버섯만 normal 변경·실행 확인 → 게살 allergy 저장 확인·소시지 high → 치즈 low·페퍼론치노 제외·실행 확인. 일부 표현은 기존 로그 성공이지만 이 축약 대본 전체는 **미검증**이다. 단독 알레르기 발화도 새 누적 문맥에서 확인해야 한다. 물리적 작업 난이도를 피하려고 없는 섭취 제한을 지어내지 않는다.
