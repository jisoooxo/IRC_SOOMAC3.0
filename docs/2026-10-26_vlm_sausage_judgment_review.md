# 2026-10-26 VLM 소시지 판정 검토 — 원인 가설·Live RAG·프롬프트·이미지 크기

→ **소시지 오판은 데이터 부족이나 참고 이미지 문제보다, 작업 전후 변화 판정 문제일 가능성이 크다(추측).** 첫 실험은 재료별 생김새 프롬프트 보강, 그다음 판정 입력 저장 → ROI 크기 맞춤 순서로 한다.

검토: Claude Code 분석 + Codex(gpt-6-astra, read-only) 교차검증 3회. 사용자 전제: VLM 오판은 소시지뿐이고, 나머지 FAIL은 실제 로봇 실패다.

## 1. 지금 구조

| 단계 | 동작 | 위치 |
|---|---|---|
| 참고 이미지 | 재료별 SigLIP2 crop 임베딩 200개의 평균에 가장 가까운 crop **1장**. 재료마다 캐시되어 늘 같은 사진 | `vlm_rag.py:41-123`, `llm_langgraph_node.py:310-320` |
| 작업 전 사진 | 직전 PASS(또는 재시도 종료) 판정의 마지막 프레임 | `llm_langgraph_node.py:418-421` |
| 작업 후 사진 | `/llm/confirm_start` 처리 시점의 최근 프레임 최대 5장. 새 프레임 도착·안정화 대기 없음 | `llm_langgraph_node.py:224-229,288,370`, `irc_control_pkg/main_vlm.py:214` |
| 판정 | Gemma4 VLM에 [참고, 작업 전, 작업 후…] + 프롬프트 → 마지막 줄 PASS/FAIL/UNCERTAIN | `vlm.py:99-131`, `vlm_prompts.py:74-112` |
| UNCERTAIN | `ENABLE_UNCERTAIN_RETAKE=False`라 FAIL과 같은 경로(재시도) | `llm_langgraph_node.py:52`, `vlm.py:206` |

학습되는 모델은 없다. 데이터 augmentation이나 라벨 추가는 “참고 사진 1장을 무엇으로 고르나”만 바꾼다.

## 2. 소시지 실패 근거

- 학습 데이터 소시지 annotation 1,110개(양파 1,326, 게살 1,144 다음). 양 부족은 아니다. 단, DB에는 재료당 200개만 넣는다(`vlm_reference_embedding.py:25,69-72`).
- 로그(세션별 가장 긴 action_history로 중복 제거): 소시지 판정 18회 중 PASS 14, FAIL 4(세션 3개: 20261011_163227, 20261025_210432, 20261025_234046). 재시도를 포함한 횟수이며 오판율이 아니다.
- FAIL 4회의 VLM 근거는 전부 “소시지칸에 변화가 없다”이다. 1회는 “작업 전에도 이미 배치되어 있고 변화 없음”. 소시지를 다른 재료로 착각한 경우는 0회다.
- ⚠ 로그에는 입력 픽셀이 저장되지 않는다(`llm_langgraph_node.py:455`). 실제 미투입인지 VLM 오판인지는 사진으로 확인하지 못했다.

## 3. 판단과 결정

| 안 | 판정 | 이유 |
|---|---|---|
| 데이터 augmentation / 새 라벨 | 보류 | 참고 1장 선택에만 영향. 실패 근거가 인식이 아니라 변화 판정 |
| Live RAG (`LIVE_RAG` 토글, 현재 장면으로 검색) | 가능, 기본값 False, 비교 실험 후 | Runtime에 SigLIP2 로드·캐시 우회 필요(1~2시간). 빈 칸으로 검색해도 가장 닮은 소시지 사진이 나와 거짓 PASS 쪽으로 기울 수 있음(추측). 작업 전 사진으로 검색하는 완화안은 Codex 반대(같은 문제 + 외형 정보 상실) |
| **재료별 생김새 프롬프트 보강** | **첫 실험** | 지금 프롬프트에 칸 위치·증가 시 PASS·가림 시 UNCERTAIN은 이미 있다. 없는 것은 재료 생김새, 대상 칸 집중, 적은 양 기준 |
| UNCERTAIN 재촬영 켜기 | 후보 | 팔이 칸을 가린 순간에 찍혔다면 재촬영이 가장 싸게 고친다(추측) |
| 전후 ROI 크기 맞춤 | 두 번째 실험 | 아래 §4 |

**사용자 결정: 소시지 PASS 기준은 “소시지가 들어갔다”이다(주문량 충족이 아님).** 한두 조각이라도 새로 들어갔으면 PASS.

## 4. 이미지 크기

Gemma4 전처리는 이미지마다 비율을 유지한 채 `max_soft_tokens=280` → 약 645,120px로 **확대 또는 축소**한다(`transformers/.../image_processing_gemma4_unified.py:54-78`, 지원 토큰 70/140/280/560/1120).

- 참고 소시지 crop(중앙값 217×401) → 약 2.2배 확대. 카메라 전체 프레임 → 축소. 실제 소시지칸은 작게 보인다.
- 맞추는 법: 작업 전·후 프레임에서 **같은 좌표·같은 여백(칸 테두리 포함)** 으로 소시지칸 ROI를 자른다 → 비율 유지 정사각 패딩 → **768×768**(정사각 상한 803px를 48 배수로 내림, 256토큰). `max_soft_tokens`는 280 유지.
- 참고 사진은 생김새 확인용으로 둔다. 768로 맞춰도 물체 비율이 달라 축척은 같아지지 않는다. 축척은 **전후 ROI끼리** 맞춘다.
- 맥락용 전체 장면 1장은 유지(맞는 칸인지, 칸 밖에 떨어졌는지). 후 프레임은 가림 없는 선명한 1~2장.
- ROI 고정 좌표는 카메라·도시락 위치가 고정일 때만 가능하다(현재 UNKNOWN). 이미지 구성을 바꾸면 프롬프트의 “이미지1/이미지2…” 설명도 함께 바꾼다.

## 5. 평가 방법

1. 판정마다 참고·작업 전·작업 후 원본 전체, 촬영 시각, comparison 출처, VLM 원문을 세션 폴더에 저장한다.
2. 같은 저장 입력으로 기존 / 프롬프트 보강 / ROI / 둘 다를 비교한다.
3. 소시지 실제 미투입과 다른 재료의 실제 로봇 실패를 음성 사례로 넣고 거짓 PASS·거짓 FAIL·UNCERTAIN을 따로 센다. 재시도 후 `policy_success`를 정답으로 쓰지 않는다(`vlm.py:225`).

## 6. 적용 — 재료별 생김새 프롬프트 (2026-10-26, 미커밋)

- 참고 crop을 직접 확인한 결과, 참고 사진은 검은 도시락이 아니라 **재료 공급 용기(흰·투명 트레이)** 를 확대한 사진이다. 소시지 트레이에는 통소시지가 10개 넘게 들어 있다. 화면에 공급 트레이가 함께 보이면 VLM이 그것을 “이미 있음”으로 봤을 수 있다(추측, 사진 미확인).
- `vlm_prompts.py`: `INGREDIENT_GUIDES`(재료별 칸·생김새)를 추가해 첫 작업·비교 작업 프롬프트에 넣었다. 공급 용기 속 재료는 판정에 쓰지 않는다는 지시도 넣었다. 페퍼론치노 문장은 페퍼론치노에만 붙이고, 조사(이/가, 은/는)를 받침에 맞췄다.
- “한두 조각이라도 들어갔으면 PASS, 양은 판정하지 않음”은 **소시지에만** 적용한다(`INSERTION_ONLY_INGREDIENTS`). 다른 재료 기준은 그대로다.
- Codex 교차검증 반영: 양파·버섯 설명 확대, 넓은면·넓적면은 참고 사진이 따로 없어 “노란 건조 파스타 면”으로만 적음, 완화 규칙 범위 한정.
- 테스트: `src/soomac_irc/test/test_vlm_prompts.py` 신규. VLM·baseline 포함 420 passed.
- ⚠ 문자열 테스트 통과는 실제 오판 감소의 증거가 아니다. 로봇 실행으로 소시지 PASS/FAIL과 다른 재료의 거짓 PASS 여부를 확인해야 한다.

## 용어 정리

ROI: 이미지에서 관심 영역만 잘라낸 부분(여기서는 소시지칸). RAG: 판정 때 참고 자료를 검색해 함께 넣는 방식. 토큰: 이미지를 모델 입력 단위로 나눈 조각 수. (내가 의역해보자면, 소시지를 못 알아보는 게 아니라 “늘었는지”를 못 보는 것 같으니 칸을 크게 잘라 보여 주고 무엇을 볼지 정확히 말해 주자는 것이다.)
