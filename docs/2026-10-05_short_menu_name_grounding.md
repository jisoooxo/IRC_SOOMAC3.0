# 2026-10-05 짧은 메뉴명 근거 검사 — 미결 과제

[가드 정리 계획](2026-10-05_guard_cleanup_plan.md)

**한 줄 요약: 두세 글자 메뉴명은 STT 오타와 다른 음식이 글자 비교로 구분되지 않는다. 지금은 통과시키고 있으며, 처리 방법을 정해야 한다.**

---

## 1. 무엇이 문제인가

자모 유사도 검사([llm_policy.py](../src/soomac_irc/soomac_irc/llm_policy.py)의 `menu_grounding_distance`)는 거리 0.35 이하를 "발화에 나온 메뉴"로 인정한다.

메뉴명이 짧으면 자모 하나 차이도 거리가 0.20 밖에 안 된다. 그래서 STT 오타와 전혀 다른 음식이 같은 점수를 받는다.

```text
"양판" → 양파   자모 1개 차이  0.20  (STT 오타 → 통과시켜야 함)
"오이" → 오일   자모 1개 차이  0.20  (다른 음식 → 막아야 함)
```

Cause: 거리는 "글자가 얼마나 다른가"만 재고, "실제로 있는 다른 단어인가"는 모른다.
Effect: 모델이 "오이"를 오일로 바꿔 출력하면 Python 이 그대로 통과시킨다. (Codex 교차검증에서 발견, 함수 실행으로 재현)

## 2. 실측 (2026-10-05, 현재 코드)

마지막 두 줄을 보면 **같은 "페퍼로니"도 주변 글자에 따라 점수가 0.27~0.36 으로 흔들린다.** 기준선 근처라 결과가 불안정하다.

## 3. 왜 글자 비교로는 안 되나

STT 오타와 다른 음식을 가르려면 "오이는 실제로 있는 다른 음식"이라는 지식이 필요하다.

그 지식을 코드에 넣으면 **음식 단어 목록**이 되고, 단어 하드코딩 금지 원칙에 걸린다.

## 4. 선택지

| | 방법 | 동작 | 장점 | 단점 |
|---|---|---|---|---|
| A | **짧은 메뉴는 한 번 되묻기** | 3글자 이하 메뉴가 0이 아닌 거리로 매칭되면 `menu_confirmation` 으로 보낸다. "양판" → "양파 말씀이시죠?" | 이미 있는 되묻기 경로 재사용. 단어 목록 불필요 | STT 오타 때 한 턴 더 걸림 |
| B | 그냥 둠 | 지금처럼 통과. 응답이 "오일 반영했어요"라고 말함 | 대화가 가장 빠름 | 사용자가 듣고 직접 고쳐야 함 |
| C | STT 단계에서 메뉴 인식률 개선 | STT 에 메뉴명을 우선 인식하도록 힌트를 준다 (`stt_hotword.py` 쪽) | 오타 자체가 줄어 A 의 되묻기 빈도도 줄어듦 | STT 작업이라 시간이 더 걸림. 실제 마이크 검증 필요 |
| D | 모델 튜닝 | "오이 → 오일" 같은 치환을 하지 않도록 학습 데이터 추가 | 근본 원인(모델 치환)을 줄임 | 튜닝 일정에 묶임. 0 이 되지는 않음 |

**추천: A + C (+ 튜닝할 때 D 데이터 같이)**
- A 로 틀린 메뉴가 확인 없이 들어가는 걸 먼저 막는다.
- C 로 오타 자체를 줄여 A 의 추가 질문 비용을 낮춘다.
- 알러지 해제 오출력을 튜닝으로 잡을 때 D 데이터를 같이 넣는다.

## 5. A 를 고를 경우 구현 메모

- 위치: `grade_menu_grounding` ([llm_policy.py](../src/soomac_irc/soomac_irc/llm_policy.py)) 의 거리 판정
- 조건: `len(메뉴명) <= 3` 이고 `0 < 거리 <= 0.35` → `uncertain` (되묻기)
- 거리 0 (글자 그대로 포함)은 통과 유지. 단 "크림빵"처럼 다른 단어 안에 메뉴명이 들어간 경우는 이 방법으로도 못 막는다.
- 길이 기준과 거리 기준 둘 다 숫자라 단어 목록이 필요 없다.
- 영향받는 테스트: `test_guard_cleanup_regression.py` 의 STT 변형 통과 테스트(양판, 계살)가 "되묻기"로 바뀐다.

## 6. 정해야 할 것

1. A / B / C 중 무엇으로 갈지
2. A 라면 "3글자 이하" 기준이 맞는지 (페퍼론치노(5글자)처럼 긴 이름은 지금처럼 통과)
3. "크림빵 → 크림" 같은 포함 관계는 받아들일지
