## 3. 사용자 시나리오와 복합 멀티턴

사용자가 요청한 **면+소스 추천 → 크림 선택+바로 담기 → 양파/버섯low → 버섯normal 변경+실행(양파low 유지) → 게살allergy+소시지high+실행 → 페퍼론치노 제외+치즈low+실행**의 분리형·복합형·존댓말·명령형 자료를 포함한다. `바로 담아`, `바로 담아줘`, `바로 담도록 해` 등의 실행과 부정/유예 대조를 기존 검수 결과에 연결했다. 단어만 보고 무조건commit을 켜는 Python 규칙은 없다.

10대화·88기록의 기존literal-gold 흐름을 새 후보의 논리104행(D64/Q7/P33)에 결속했다. 중복11을 제외한 고유93행(D59/Q4/P30)과 input/target/route가 모두 일치한다. 물리 bridge 없는 연속 턴은 전체session 전후가 연결된다. 24개 물리 bridge는 명시된 오프라인 모의 완료이며 실제 로봇 완료가 아니다.

Q는 조건부이고 현재 고정 시작 안내 경로는P가 호출되지 않는다. 따라서 D/Q/P 행 수가 모두 같아야 하는 것이 아니다. 없는 호출의 가짜P 학습행을 만들지 않았다. 나중에 고정 시작 안내를 모델 응답으로 바꾸려면 그 경로·계약·학습 사례도 따로 검증해야 한다. 현재 단계 전환 자동 모델 호출이 주석 처리된 경로도 있어, 이벤트 데이터가 유효하다는 사실을 매 단계 자연스러운 모델 권유가 이미 작동한다는 증거로 쓰지 않는다.

전체 후보의 선행 사용자 발화 수는0~10개다. 2개 이상인 행은D1,522/Q606/P864개다. 긴history가 존재한다는 사실만으로 여러 앞선 발화가 정답에 독립적으로 기여한다고 단정하지 않는다. 보강93행의 최대 선행 사용자 발화는D/P8개이며,12개 선행 발화를 쓰는 학습 예시나 모든 복합 의미의 충분성을 이번에 인증하지 않았다. 현재 Runtime의20message 창을 새로 줄이지 않았다.

## 5. 학습 준비 판정과 다음 순서

**판정: 비활성 정제 후보 완료, 학습 실행 설정은 미확정이다.** 이전TAR·진행 중인 원격 학습·기존adapter에는 이 후보가 자동으로 들어가지 않는다.

| Agent | 전체 최대 토큰(입력+정답+EOS) | train최대 | 8,192 초과 | 설정 제안 |
| --- | ---: | ---: | ---: | --- |
| Decision | 8616 | 8608 | 610(train590) | 원문 유지 최소8616, cap9216 제안 |
| Recommendation | 4332 | 4201 | 0 | 기존8192 범위 안; 임의 양 근거 변경 없이 사용 |
| Response | 8430 | 8430 | 5(train5) | 원문 유지 최소8430, cap9216 제안 |

실제 CPU 인코딩으로 검증한cap은16,384다. 9,216은 토큰 길이에 근거한 설정 제안이며 그 길이의 GPU 메모리·배치·학습 성공을 측정한 값은 아니다. 8,192로train595행을 원문 그대로 처리할 수 없으므로history trim으로 통과시키지 않는다.

1. 다음 한 작업은 **현재 후보·prompt를 고정한 채 D/P 길이와 로컬/원격 batch·accum·저장/재개 설정을 검토**하는 것이다. GPU profile·학습 실행은 사용자 별도 승인 후 수행한다. 학습용 serializer key order 정렬 여부도 이때 확정하고, 바꾸면 바뀐 메시지 증거만 갱신한다.
2. D는 복합 선택/추천/제약+commit 누락, P는 새 선택/변경/유지/물리 완료의 사실성을 우선 비교한다. Q는104행 정책 교정과새Q 계약이 있으나 최신17턴에서Q미호출이었으므로 그 로그로Q모델실패를 확정하지 않는다. Agent별prompt-only와재학습 채택은 실제 비교로 결정한다.
3. 데이터와행순서가 바뀐 새 버전이므로 기존optimizer 체크포인트의그대로resume을 자동 적용하지 않는다. 새run 또는 승인한warm-start를 별도 기록하고 기존adapter/체크포인트는 보존한다.
4. 새adapter가 준비되면 정답 주입 없이 복합6턴·분리11턴을 D→Q→P 전체로 측정한다. before/after 필드·pending·실행 허가·plan·실제 응답을 함께 남긴다. Claude의cache ON/OFF 품질 검사는GPU소유권을 조율한 뒤별도 수행하며 cache때문에 학습 필드를 만들지 않는다.
5. 수치 편향·전역 의미 누수·12개 선행 발화/더깊은 복합 참조·실제 이벤트 모델 응답·실물 제조는 미검증 범위를 그대로 유지한다. 확인된 범위의 완료를 무한 전수감사로 되돌리지 않으며, 새 근거가 있는 영향 행만 추가한다.
