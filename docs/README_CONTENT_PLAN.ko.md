## 4. LangGraph 기반 멀티에이전트 구조 / 작업 전후 이미지 검증 / 개별 재료 검출

### 전체 시스템 흐름

README에는 아래 다섯 흐름을 하나의 정적 도식으로 연결한다. **토픽 이름의 세부 차이는 전체 로직 설명이나 도식 수록을 막는 조건이 아니다.**

1. 사용자가 UI에서 주문을 시작하고 STT가 발화를 텍스트로 변환한다.
2. Decision이 주문 변경·추천·실행 의도를 판단하고 코드가 상태와 실행 가능 여부를 검증한다.
3. 필요한 경우 Recommendation이 후보를 만들고, Response 또는 고정 실행 안내가 TTS·UI로 전달된다.
4. 실행 계획에 따라 MAIN·레일·비전·좌표 변환·매니퓰레이터 제어가 포장을 진행한다.
5. VLM이 참조·작업 전·작업 후 이미지를 비교하고, 결과에 따라 다음 작업·재시도·완료 흐름이 이어진다.

(내가 의역해보자면, LLM은 고객의 말을 주문과 실행 의도로 바꾸고, 제어부는 실제로 재료를 옮기며, VLM은 옮긴 결과를 확인하는 구성이다.)

## 용어 정리

| 용어 | 이 프로젝트에서의 의미 |
|---|---|
| LLM / VLM | 각각 자연어 주문 처리와 이미지 기반 작업 검증에 사용하는 언어 모델 / 시각 언어 모델이다. |
| 에이전트(agent) / 어댑터(adapter) | 각각 판단·추천·응답이라는 역할 / 같은 기반 모델에 역할별로 적용하는 LoRA 가중치이다. |
| 공유 상태(state) / 대화 이력(history) | 각각 현재 주문·취향·대기 질문·로봇 상태 / 이전 발화와 응답 기록이다. |
| 양자화(quantization) / QLoRA | 각각 가중치 표현의 메모리를 줄이는 방법 / 양자화된 기반 모델 위의 LoRA 학습 방식이다. |
| 접두 캐싱(prefix caching) / 워밍업(warmup) | 각각 같은 입력 앞부분의 KV 캐시 재사용 / 실제 사용자 입력 전에 공통 경로를 준비하는 호출이다. |
